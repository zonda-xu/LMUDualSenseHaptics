# v1.5.1-preview：ACC 参考路面与后轴失抓

以 v1.5 为基线。保留原有路肩识别、速度相关节奏及路肩 PCM 振荡器，保留刹车、油门和单车配置。非路肩路面、轮胎滑移与后轴失抓参考 Adudumax 的 [ACC-DualSense-Feedback](https://github.com/Adudumax/ACC-DualSense-Feedback/tree/0c84c1901842fa1b864a3445226ddd64f991ffad)，MIT 许可见第三方声明。

- 四轮以轮胎载荷变化和悬架位移建立短时冲击窗口，分配左右与前后节奏。悬架位移变化按 20 ms 参考帧归一化，避免不同遥测频率直接改变力度；单轮载荷变化不会因为四轮平均数变化而凭空触发其他车轮。原“左右分离”调节继续控制侧向串扰；100% 分离时趋近 ACC 的低串扰设计。
- 四轮正常滑移建立受限制的自适应基线，再根据纵向滑移和轮胎侧向角表达超过基线的状态。纵向滑移沿用本项目的有效半径估计，尚未学到有效半径时不能声称已知纵向滑移。
- 后轴独立联合后轮滑移角、车身横移、偏航角速度和转向，形成选择性的失抓事件，结束时逐步衰减。非零后轴提示通过独立音频振荡器输出；前轮和后轮滑移也使用独立振荡器。较强悬架/载荷冲击另驱动低频颠簸振荡器，普通路面纹理保留独立载波。
- 路肩仍由现有 `RoadSignalEngine`、`RoadHaptics` 和路肩振荡器处理。单独路肩 PCM 输出与冻结的 v1.5 合成器逐采样相同；其他信号同时发生时仍按混音与限幅规则叠加。

## 信号差异和实测边界

LMU 没有 ACC 的 `SlipVibration`、`GVibration`、`KerbVibration` 或 ACC 原生 XInput 震动输入。本版不构造这些信号，也不宣称与 ACC 逐帧或实际手感完全一致。LMU 的地面速度推算滑移角，`mLocalRot.y` 提供偏航角速度，转向使用归一化输入而非 ACC 转向角。接口字段存在并不等于每辆车都有有效输出；偏航无效时后轴事件不输出，信号方向、零值及各车型阈值需要真实驾驶验证。

路面滑移和后轴提示共用界面的“轮胎打滑”开关与强度；普通路面沿用“路面细节与冲击”；路肩沿用原有独立开关。运行信息和录制输出包含逐轮冲击、滑移、后轴状态与偏航有效性，便于实车判断；检测强度并不直接等于硬件实际输出。切换车、暂停、遥测过期、物理时间跳变会清除旧事件，防止旧车辆的反馈残留。车载轮胎载荷为零时，悬架位移仍可产生非路肩冲击；轮胎压缩继续用于接地判定。

自动测试涵盖四轮独立定位、轮胎滑移和后轴事件、恢复尾音、异常与过期帧、音圈通道、原有路肩 PCM 对照、HID 及现有车型切换和扳机回归。Windows 自动构建和合成回放不是实体 DualSense 或真实 LMU 驾驶验证；不要将这些结果解释为已经完成手感标定。

ACC 参考场景与自动化测试对应关系见 [ACC 参考回归测试](ACC_REFERENCE_TESTS.md)。
