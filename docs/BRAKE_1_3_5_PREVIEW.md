# v1.3.5-preview：踏板曲线、持续滑移信息与短事件

## GT3：核对 v1.0.1

自动模式按当前车辆类别反复识别 GT3，每次换车重新路由和清理事件状态。GT3 使用 v1.0.1 的基础曲线 `[3,4,4,5,5,6,6,7,7,8]`、ABS 15 Hz 优先级、抱死 8 Hz、信号包络和事件选择规则。恢复该版本的 `LockRatio` / `LockFullRatio` 参数，默认 0.30 / 0.60。

测试直接使用仓库 v1.0.1 标签的 SignalEngine、TriggerEngine 源码作为对照，仅调整测试命名空间。源码哈希受静态检查保护；同一完整遥测序列在两个实现中运行，比较 ABS/抱死信号和最终 L2 指令，包括轮径学习、正常制动、ABS/抱死交叠、恢复及非默认阈值。手动 ABS 模式仍是明确的用户覆盖选项。

## 无 ABS：独立基础曲线

基础阻力在有效驾驶时预先设置好，不等待刹车或轮胎事件：

`level(x) = ceil(baseGain × [start + (end - start) × x^exponent])`

`x` 为手柄十个硬件区间的相对行程，默认起段 2、末段 6、指数 1.4，均指 100% 基础强度时的等级。默认 50% 强度约为 1–3 级。界面可分别调整起段、末段和指数；这条曲线不随车速、轮胎载荷或风险变化，也不表示剩余抓地力。

开启且强度非零时最低为 1 级；设为 0 或关闭时完全关闭。固件只有 8 级，极低滑块设置可能整段都是 1 级，不能承诺连续分辨每一个百分比。已有个人配置保留，原先很低的基础强度将从可能无输出变为最低有效等级。

## 持续信息与事件的切换

正常滑移风险使用 `0x21` 渐进阻力：在基础曲线上叠加最多 3 级、随风险和行程增加的阻力。风险仍来自逐轮有效纵向接触区滑移及有界趋势，不把满刹、横向滑动或缺失信号当作锁止。原有预警滞回与短保持用于避免阻力在门槛附近闪断，不再输出 12 Hz 临界振动。

明显抱死进入时，使用 24 Hz 全行程短脉冲，默认 120 ms。持续抱死随后由持续增阻表达，同一事件不会周期性重发脉冲。实测滑移回落到临界阈值以下、持续达到保持时间后才重新允许一次警报；松刹、失效、低速、换车及暂停按原规则取消事件。

脉冲两端各用约 20 ms 调整幅度，从当前行程的持续阻力编码进入/退出；短脉冲结束后恢复当时的完整静态曲线。模式切换期间无法同时输出静态墙。振动幅度与静态力是不同物理模式，相同等级不保证真实指感连续，仍须在 DualSense 上复测。过高基础强度会占用 8 级输出上限，减少风险增阻余量。

若可信参考墙与实时滑移同时存在，每个区间只使用二者较大的增阻量，避免对同一制动风险重复加力；事件脉冲优先。输出来源为 `BrakeBase`、`BrakeReference`、`BrakeLimit` 或 `LockPulse`。

## 学习参考墙：先测覆盖，不扩充模型

本版保留工况隔离、每次制动最多一个有效起点、至少三个同工况样本及置信度门槛，没有增加分箱或跨工况迁移。基础脚感和实时滑移增阻完全不依赖学习覆盖率。

诊断记录增加累计有效起点、已采样工况数、当前帧是否接受样本、实测起点输入，以及参考墙是否实际改变最终静态输出。仅有置信度合格不算“实际启用”：若墙被更强滑移阻力覆盖、输出饱和、强度关闭或事件脉冲替换，就不计入实际墙输出。

运行完整生产链回放后，可以统计：

```powershell
dotnet run --project tests/LMUDualSenseHaptics.Tests -c Release -- --replay recording.jsonl replay.jsonl
python scripts/evaluate-brake-reference.py recording.jsonl replay.jsonl
```

- 覆盖率按不重复的有效物理帧计算，分母是四轮滑移有效、达到驾驶速度且有参考位置的帧，包含未踩刹车时预装的墙；不把 250 Hz 输出次数当成独立观测。
- 记录独立有效起点数量、样本分布及单工况最多样本数，分别给出参考就绪和实际输出比例。
- 位置偏差只用起点到来前已经输出的、同车同工况、间隔不超过 100 ms 的参考位置对照实测起点，避免拿该起点刚学到的模型评价自身。输出为刹车输入百分点，包含保守余量，不是最佳制动点误差。
- 同次制动触及参考墙后仍未出现实测阈值滑移，记为“未确认”，不直接认定为误报；驾驶者可能已经响应提示松刹。数据中断或换车导致的未完成事件单独统计。
- 没有可评分样本时，偏差为 `null`；缺少独立真值标签时，误提示率为 `null`。零覆盖不代表零误差。

单一工况只有一个样本时，无法可靠估计跨工况迁移误差；本版不通过直接合并来制造置信度。新测试为合成数据，用户日志及其派生数据不进入公开仓库。

## 参考和本版贡献

Codemasters 高级游戏设计师 Steven Embling 在 [PlayStation Blog 的 F1 22 说明](https://blog.playstation.com/?p=366243) 中，将扳机阻力关联到轮胎滑移率，并描述了独立静态阻力。该文章说明的是 F1 22 的行为，没有公开具体控制公式，也不能直接当作 F1 25 内部实现。

本版在 LMU 数据和 DualSense 单一效果模式的限制下，把独立踏板曲线、持续滑移增阻、可重新触发的短事件分开，并增加参考墙的实际覆盖和未参与当前学习样本的预测检查。新增价值在于可验证的输出时序及诊断；没有声称这是新的轮胎物理模型，也未复制 Codemasters 的未公开算法。

验证包括 v1.0.1 源码对照、全链路遥测至 HID 测试、持续严重滑移下单次脉冲、恢复重触发、基础曲线与风险独立性、参考墙计数及离线统计。真实力度、模式切换体感和驾驶收益仍需实机评估。
